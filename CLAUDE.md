# CLAUDE.md: Battlecard

BattleCard: customizable battle card builder with game icons + PNG export (battlecard.neorgon.com)

**Live:** battlecard.neorgon.com · **Port:** 8823

## Run

```bash
make serve
```

Then open http://localhost:8823. It must be served over HTTP. The app is ES modules, and `file://` blocks them.

## Conventions

- Zero build step. Plain ES modules loaded by `js/app.js`.
- Header and footer come from the shared kits. Do not add site-local `.neo-footer` or `.header-bar` CSS.
- No single JS file over ~500 lines. It currently holds.

## Gotchas

- **PNG export needs html2canvas-pro, not html2canvas.** `color-mix()` on `.section-icon-wrap` computes to `color(srgb ...)`, which html2canvas 1.4.1 cannot parse, so every export threw. The fork is pinned to an exact jsdelivr path with SRI, and `script-src` allows only that file: an upgrade changes the URL, the `integrity` hash and the CSP together.
- **`normalizeCard` is the only door for outside data**: share links (`#c=`), JSON import, localStorage and templates all pass through it. `render.js` writes `logoDataUrl`, `accentColor` and each section `id` into HTML attributes, so each is checked against what the app itself produces (a base64 image data URL, a hex colour, `[A-Za-z0-9_-]`), not just `typeof`. A crafted share link once broke out of all three. A new field that lands in markup needs the same check; logo uploads go through `safeLogo` as well.
- **The CSP is strict and lives in the `<meta>` tag.** `script-src` has no `'unsafe-inline'`: the header kit's theme guard is the one inline script and is allowed by its sha256, so editing it means re-stamping the hash (smoke check 29 flags a stale one). No `on*=` attributes and no inline `<script>`, including in HTML the app writes into another window: `exportView`'s new tab inherits this policy, which is why it strips `contenteditable` before writing. Hosts are exact (no `*.convex.cloud` or `*.workers.dev`), and `frame-src 'none'` also stops a same-origin frame of a file with no policy, such as `/robots.txt`.
- **`base-uri` is `'self'`, not `'none'`.** html2canvas-pro inserts `<base href="<page URL>">` into its clone iframe, which inherits this policy, so `'none'` logs a violation on every export. `'self'` still refuses an injected `<base>` to another origin.
- **The `onclone` / `ignoreElements` options in `exportPNG` are load-bearing.** Without them the PNG is faded (the clone replays `fadeIn`), unstyled in Firefox (the cloned CSP meta resolves `'self'` against `about:blank`), and unstyled in WebKit with html2canvas-pro 2.x (the clone reports loaded before its stylesheets arrive). A check that only asserts "a PNG downloaded" passes all three; compare a pixel against the live render.
